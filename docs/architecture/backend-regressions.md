# 双后端回归审查

本轮对照起点为 `main` 的 `479de3d` 与双后端分支的 `37209e4`。本记录以 Codex 单后端 `main` 的产品行为为基线，审查双后端引入的共享流程变化与 Claude 消息适配。测试使用临时目录、模拟传输及隔离浏览器，原生运行测试使用真实 Claude CLI/SDK 和本地模拟 Messages 服务。

## 已修复问题与依据

- 旧网页未分类目录：网页配置根目录迁移后，分类只接收新根路径。管理器现同时发布当前根路径与所属 Codex 配置中的旧根路径；已固定目录、明确项目归属、其他创建者及子目录继续按原规则分类。
- 桌面未分类索引：索引曾路由到当前后端，使 Claude 选择期间读取错误的原生目录。管理器统一从 Codex 状态读取；启用状态与当前模型独立。
- 用户消息 Markdown：气泡曾直接输出文本。现复用现有安全 Markdown 渲染器；文件引用通过文本节点转换，代码、公式及已有链接保留语义，复制与编辑保留源码。
- Claude 内部记录：后台通知、合成消息和仅供原生终端显示的中断记录曾创建用户气泡及轮次。转换现依据原生来源字段区分；工具结果继续更新工具项，用户输入相同正文保持可见。自动唤醒采用保存的轮次锚点。
- 子代理事件归属：转发的子代理帧曾先经过主会话的自动轮次、任务和用量处理。现先隔离转发帧与重放帧，再处理主会话生命周期。
- 旧项目模型偏好：服务端只读取新配置目录。目标文件缺失时读取旧网页偏好，修改时将完整内容写入新目录，已有目标文件优先。
- 项目偏好同步：激活后端曾关闭同步而未重新开启；跨后端共享单个在途写入还会阻塞新后端保存。现激活后重新同步，按后端管理写入，并检查连接实例隔离旧响应；默认模型及思考强度从所属后端配置读取。
- 初始化迟到：启动时的旧模型与配置响应可能覆盖期间切换的对话或后端。初始化应用设置前检查启动时后端与导航版本，列表恢复继续按原有打开版本保护。
- 单后端恢复：桥接整体保持在线时，所属后端由未就绪恢复为就绪会重新恢复模型、历史和写入状态，保留原消息区及草稿。额度、技能及待核对输入跟随后端就绪状态停止和恢复读取；队列刷新按请求版本隔离迟到结果。
- 后端目录迟到：模型目录和账户读取现同时检查激活版本、后端、目录及连接实例，断线或替换连接后停止应用旧结果。
- 列表初始化失败：启用后端构造失败时曾直接从汇总列表中消失。现将其保留为有明确后端标识的读取错误，已有记录由前端保留及提供重试。
- 证书与登录迁移：自动证书与登录文件随目录切换重新创建。现只在目标目录缺失时原子复制已有网页自有文件，保持受限权限及旧文件；证书对缺失时提供明确错误。
- 后端启停列表：停用后端后曾只更新后端配置，所属对话与当前对话保留到页面刷新。现由桥接状态通知触发列表重新读取，停用后立即移除所属对话，正在查看的所属对话回到新对话，并清除被停用后端的模型选择；重新启用后恢复显示。

## 网页交互对照

使用 `tests/browser/backend-interactions.mjs` 对 `main` 与双后端各自的独立生产构建执行相同步骤，覆盖工作区收放、搜索弹窗、技能目录、运行中模型选择、思考强度键盘收起、Enter 换行、草稿保留、深浅主题、80%～200% 缩放与手机侧栏。构建目录通过 `UI_BUILD_DIR` 指定，`UI_MAIN=1` 标记基线；修复前双后端构建通过 `UI_BEFORE=1` 记录退化状态。截图和几何数据保存在 `.cache/backend-interactions/`。双后端额外通过 Chrome 设置中的实际页面缩放验证桌面与窄屏各自的深浅主题及五档缩放，核对 `devicePixelRatio`、实际视口、输入框高度和控件边界；结果位于其 `browser-zoom/report.json`。

- 同供应商的模型选择保留 `main` 在运行期间为下一轮调整参数的操作；跨供应商调整等当前轮次结束后进行。
- Claude 同供应商切换模型保留技能、命令和代理目录，恢复连接及刷新配置时保留同一账户已读取的额度。
- 新草稿先恢复已选择的供应商，再读取所属模型、账户及项目偏好，避免初始化的原生默认值替换供应商选择。
- 窄屏保留顶部项目名称及目录选择入口，后端标识继续采用独立图标。
- Claude 原生额度窗口到期后自动校准；Codex 同一账户切换工作目录时保留已展开的额度详情。
- 信息提示层保持可见并让鼠标事件到达下方控件，验证已有 `AGENTS.md` 提示仍显示时点击发送重试。
- 旧浏览器脚本改为操作实际富文本输入；详情重置脚本显式展开默认折叠的项目后再切换对话。

## 验证入口

- `server/tests/backend-product-contract.test.mjs`：两端实际适配器执行同一套网页操作，覆盖离线偏好、旧目录继承、保存成功通知、验证和写入失败后的重试、目录创建、整理占用及历史读取。传输为模拟 app-server，Claude 仅检查版本，原生模型执行单独验证。
- `server/tests/codex-close-lifecycle.test.mjs` 与 `subscriptions.test.mjs`：取消订阅确认和实际关闭分别到达、顺序交换、断线清理及关闭后重新恢复。`tests/integration/codex-subscription-release.mjs` 通过真实 CLI 和适配器执行八组立即重新打开，使用人工历史，模型轮次数为零。原生响应语义见 [app-server 协议](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md)。
- `server/tests/backend-routing.test.mjs`：工作区根据适配器所有者声明路由，浏览器关闭只通过 `releaseClient` 释放所属代理；管理器保持与原生订阅集合隔离。`tests/architecture.test.mjs` 同时核对公共桥接、原生适配器和 HTTP 的依赖边界。
- `client/tests/backend-connection-recovery.test.js` 与组件输入队列回归：单后端恢复、另一后端状态隔离、草稿保留及队列迟到隔离。
- `client/tests/thread-order.test.js`：新旧目录、来源判定、明确归属、完整分页、活动排序及迟到事件。
- `client/tests/backend-project-models.test.js`：激活后项目同步、原生默认强度、跨后端在途写入与缓存隔离。
- `server/tests/backend-routing.test.mjs`：相同原生标识隔离、后端初始化失败及全局未分类索引。
- `server/tests/claude-internal-history.test.mjs`：后台通知、中断、合成记录与相同文字的人类输入。
- `server/tests/project-models.test.mjs` 与 `web-config-migration.test.mjs`：旧配置继承、目标优先、原文件保留及文件权限。
- `tests/integration/claude-message-provenance.mjs`：真实 SDK 读取临时原生记录，验证来源字段在历史恢复中保留。
- `tests/browser/backend-regressions.mjs`：生产构建下的分组、Markdown、引用键盘打开、Claude 历史、刷新、深浅主题、规定缩放和窄屏。截图及构建来源保存到 `.cache/backend-regressions/`。

- `tests/browser/history-performance.mjs`：完整 33 页与 3210 条隔离记录、最近消息先显示、历史前插阅读位置、草稿及迟到分页隔离。
- `npm run check`：版本、架构、格式、单元、组件及临时全局安装。

真实模型服务调用与真实外部账户额度需要对应环境单独验证；模拟 Messages 服务验证原生调用链、参数及生命周期。测试结果按实际执行来源报告。
